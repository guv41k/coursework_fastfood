# 🍔 FastFood — информационная система «Точка общепита»

Десктопное приложение на **Go** для учёта кассиров и заказов сети точек быстрого питания.
Главная особенность проекта — **структуры данных для хранения и поиска написаны с нуля**, вместо встроенных `map` и готовых библиотек:
хеш-таблица, бинарное дерево поиска и односвязный список. Они лежат в основе поиска и построения отчётов.

> Учебный проект (курсовая работа). Цель — показать работу с алгоритмами и структурами данных, дженериками, слоистой архитектурой и GUI на Go.

## Возможности

**Кассиры**
- добавление, удаление, поиск по паре «ФИО + адрес точки»;
- удаление запрещено, если у кассира есть заказы (контроль целостности связей);
- загрузка из файла и сохранение в файл.

**Заказы**
- добавление (кассир выбирается из существующих), удаление;
- поиск всех заказов кассира на конкретной точке;
- загрузка из файла и сохранение в файл.

**Отчёт** — выборка заказов по адресу точки, дате и сумме с подтягиванием данных кассира (аналог `JOIN` между заказами и кассирами).

**Для наглядности алгоритмов**
- при каждом поиске показывается **число шагов** (проб в хеш-таблице / сравнений в дереве);
- пункт «Показать структуры» выводит внутреннее состояние хеш-таблицы (ячейки, статусы, шаги пробирования) и дерево заказов в виде ASCII-схемы;
- размер хеш-таблицы (15–20) выбирается при запуске — удобно наблюдать коллизии и заполнение.

**Устойчивая загрузка данных** — некорректные строки не ломают загрузку: они пропускаются, а в итоговом окне показывается, сколько записей загружено, сколько пропущено и по какой причине (с номером строки).

## Структуры данных

| Структура | Файл | Где используется | Особенности |
|---|---|---|---|
| Хеш-таблица `HashTable[V]` | `ds/hashtable` | индекс кассиров по ключу `ФИО\|адрес` | открытая адресация с линейным пробированием, хеш djb2, «надгробия» (`deleted`) при удалении, подсчёт шагов поиска |
| Бинарное дерево поиска `BST[K, V]` | `ds/tree` | индекс заказов по `ФИО\|адрес` и по дате | дженерик с произвольной функцией сравнения, удаление узла с двумя потомками через преемника, ASCII-визуализация |
| Односвязный список `LinkedList[T]` | `ds/linkedlist` | хранение нескольких заказов под одним ключом дерева | дженерик, удаление по предикату |

Заказы хранятся в одном срезе, а оба дерева и хеш-таблица хранят только **индексы** в нём. При удалении последний элемент среза переносится на место удалённого, а индексы в индексах обновляются (`UpdateValue`) — удаление остаётся `O(1)` по срезу.

## Архитектура

```
.
├── FastFood/                 # Go-модуль приложения
│   ├── main.go               # точка входа, диалог выбора размера хеш-таблицы
│   ├── ui/                   # GUI на Fyne: главное окно, таблицы, контекстные меню
│   ├── managers/             # бизнес-логика: CashierManager, OrderManager, BuildReport
│   ├── models/               # доменные модели и валидация
│   │   ├── cashier/          #   кассир (ФИО, адрес, оклад)
│   │   ├── order/            #   заказ (кассир, адрес, дата, время, сумма)
│   │   └── date/             #   собственный тип даты с учётом високосных годов
│   ├── iodata/               # чтение/запись текстовых файлов
│   └── ds/                   # собственные структуры данных
│       ├── hashtable/
│       ├── tree/
│       └── linkedlist/
└── catalog/                  # примеры входных данных (корректные и с ошибками)
```

Слои зависят только «вниз»: `ui → managers → models / ds`. GUI не знает о внутреннем устройстве индексов, а менеджеры не знают о GUI.

## Валидация

- **ФИО** — ровно три слова, кириллица, каждое слово с заглавной буквы (`Иванов Иван Иванович`);
- **Адрес** — непустой, без символа `;` (он является разделителем в файлах);
- **Оклад / сумма** — строго положительное число;
- **Дата** — формат `ДД.ММ.ГГГГ`, проверка числа дней в месяце и високосных годов;
- **Время** — формат `ЧЧ:ММ`, `00:00`–`23:59`;
- **Заказ** можно создать только для существующего кассира; **кассира** нельзя добавить повторно (пара «ФИО + адрес» уникальна).

## Формат файлов

Текстовые файлы в кодировке UTF-8, одна запись на строку, поля через `;`.

`cashiers.txt` — `ФИО;адрес;оклад`
```
Иванов Иван Иванович;ул. Ленина, 10;45000.00
```

`orders.txt` — `ФИО кассира;адрес;дата;время;сумма`
```
Иванов Иван Иванович;ул. Ленина, 10;05.01.2025;14:30;450.00
```

В папке [`catalog/`](catalog) лежат готовые наборы данных. Файлы `*_with_errors.txt` содержат намеренно некорректные строки (неверная дата, время `25:99`, не хватает полей, ФИО латиницей) — на них удобно проверять обработку ошибок при загрузке.

## Запуск

**Требования**
- Go (версия указана в `FastFood/go.mod`);
- C-компилятор и системные зависимости для Fyne (на macOS — `xcode-select --install`; для Linux/Windows см. [документацию Fyne](https://docs.fyne.io/started/)).

```bash
git clone <URL-репозитория>
cd coursework_fastfood/FastFood
go run .
```

**Сборка бинарника**
```bash
cd FastFood
go build -o fastfood .
./fastfood
```

**Быстрая демонстрация**
1. Запустите приложение и выберите размер хеш-таблицы (например, 17).
2. Правый клик по таблице кассиров → **Загрузить…** → `catalog/cashiers.txt`.
3. Правый клик по таблице заказов → **Загрузить…** → `catalog/orders.txt`.
4. Попробуйте **Найти**, **Отчёт** и **Показать структуры**.
5. Загрузите `*_with_errors.txt`, чтобы увидеть отчёт о пропущенных строках.

> Загрузка нового списка кассиров сбрасывает текущие заказы — заказы всегда привязаны к существующим кассирам.

## Стек

- **Go** — дженерики, пакетная структура, обработка ошибок через `error`;
- **[Fyne v2](https://fyne.io/)** — кроссплатформенный GUI (кастомный виджет строки таблицы с контекстным меню).

## Ограничения и идеи развития

- хеш-таблица имеет фиксированный размер и не расширяется — при заполнении добавление кассира вернёт ошибку (динамическое расширение с рехешированием);
- бинарное дерево не балансируется — в худшем случае (отсортированные ключи) поиск вырождается в `O(n)` (AVL или красно-чёрное дерево);
- нет автотестов — в первую очередь стоит покрыть `ds/*` и валидацию моделей;
- данные хранятся в текстовых файлах (подключение SQLite / PostgreSQL).
